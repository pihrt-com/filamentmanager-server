# PrusaSlicer integration

FilamentManager can read estimated filament use from a text `.gcode` or Prusa binary `.bgcode` file generated by PrusaSlicer. Importing creates a ready print job; it never changes spool weights immediately. Open the job, verify the printer and the physical spool assigned to every used extruder, optionally correct actual use, and select **Complete and deduct** only after a successful print.

BGcode version 1 is supported. The importer reads printer and print metadata blocks directly, validates their CRC32 checksums when present, and supports standard uncompressed or Deflate-compressed metadata. G-code instruction blocks and thumbnails are not decoded or retained.

## Manual import

Open **Print jobs**, choose a printer and a `.gcode` or `.bgcode` file, and select **Import G-code**. The server reads metadata such as `filament used [g]`, material type, color, printer profile, and estimated printing time. The uploaded G-code itself is not retained.

## Automatic post-processing on Windows

1. Install a current Python 3, verify that `py -3 --version` works in Command Prompt, and install the current CA bundle with `py -3 -m pip install --upgrade certifi`.
2. In FilamentManager Server, open **Settings**, create a restricted integration token, and copy it immediately. The server stores only its hash and cannot display it later.
3. Create these Windows user environment variables: `FILAMENTMANAGER_URL` with the public server base URL, `FILAMENTMANAGER_TOKEN` with the generated token, and `FILAMENTMANAGER_PRINTER` with the exact printer name used in FilamentManager, for example `MK4-1`.
4. In PrusaSlicer open **Print Settings > Output options > Post-processing scripts** and enter `python "C:\path\to\filamentmanager-prusaslicer.py"`.
5. Export a `.gcode` or `.bgcode` file and confirm that a new ready job appears under **Print jobs**.

One printer name is configured per process environment. If one computer exports for several printers, use small wrapper scripts that set `FILAMENTMANAGER_PRINTER` before starting the helper, or use manual import and choose the printer in the browser.

The helper reads metadata and sends a small JSON request over HTTPS. It does not modify the G-code. PrusaSlicer's `SLIC3R_PP_OUTPUT_NAME` value is used to preserve the original exported filename even though post-processing runs against a temporary `.pp` file. Every success or failure is appended to `%LOCALAPPDATA%\FilamentManager\PrusaSlicer\filamentmanager-prusaslicer.log`. Network or server errors are also written to PrusaSlicer's post-processing output but deliberately return success so an unavailable inventory server does not block G-code export.

## Security and troubleshooting

- Use HTTPS and never place the integration token in a public repository or shared screenshot.
- Revoke a lost or unused integration token immediately in **Settings**.
- A printer-name error means `FILAMENTMANAGER_PRINTER` does not exactly match an active server printer.
- A missing-usage error means the text or binary file does not contain the `filament used [g]` metadata.
- If automatic import fails, first verify the same file with manual import. Then run the matching CMD wrapper manually and inspect `%LOCALAPPDATA%\FilamentManager\PrusaSlicer\filamentmanager-prusaslicer.log`.
- If the log reports a TLS certificate verification failure while the server opens normally in a browser, update Python and run `py -3 -m pip install --upgrade certifi`. Never disable HTTPS certificate verification.
